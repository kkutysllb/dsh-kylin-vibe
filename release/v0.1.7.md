本版本只修一个工具面缺陷：**审批门在宿主不呈现审批卡的会话里发必败 `ask`**，
两个表现（DSH 与 QiLin 同源实现一致）：

1. 非交互会话（委派子代理 / headless）：agent 调 `graphrag_index` 建库索引必失败，
   工具结果报 `Error: the user rejected tool "graphrag_index"`——用户从未见过审批卡，
   更没有拒绝过；
2. 桌面端把工作区权限设为**「完全权限」**（用户上报 2026-11-18）：agent 调
   `graphrag_index` 直接被拒；改回「工作区修改」反而弹出审批卡——**权限越宽
   越严的语义倒挂**。

---

## 修复

### 症状

用户在会话里让 agent 创建知识库并索引（如 `{create: true, kb: "音乐mv 制作",
roots: [...]}`），工具调用直接返回：

```
Error: the user rejected tool "graphrag_index"
```

agent 据此向用户报告"任务被拒绝"，建库/索引流程死锁；用户实际从未看到或
回答过任何审批卡。

### 根因

四层叠加（DSH 与 QiLin 同源实现一致）：

1. 插件审批门（`src/tool.ts` 的 `tools/pre-execute`）对 `graphrag_index` /
   `graphrag_forget` 一律发 `ask` 决策；
2. 宿主 `ApprovalService.decide`（`packages/interaction/user-approval`）对
   `approval policy = never` 的会话**先于任何应答者把 ask 确定性解析为
   `rejected`**——委派子代理在创建时即被种子 `approval/policy: never`
   （subagent `child-agent.ts`），headless 启动与权限预设同样可致；
3. 宿主把 `rejected` 结果映射为固定文案 `the user rejected tool "…"`
   （core/tools `serviceAsk` / `pipeline.ts`）——把**自动拒绝**表述成了
   **用户拒绝**；
4. **插件只识别了 `never` 的半边语义，漏了沙箱半边**：两引擎的「完全权限」
   权限预设是 `sandbox: danger-full-access` + `approval: never` **两旋钮同写**
   （base bundle cordis.patch.yml；permission-presets 的 switch 逐会话双写）。
   同一个 `approval: never` 承载两种意图——桌面完全权限（**预授权，直接执行**，
   引擎原生工具的约定是「full-access 权限**或** approval 二选一」，见
   plugin-manager 工具描述）与无人值守（CI/headless，**fail-closed**）；
   区分二者靠沙箱模式。审批门没有读 `sandboxPolicy`，把「完全权限」错当
   无人值守处理——于是权限越宽越严。

即：审批门问了一个必败的问题（非交互会话），或在用户已预授权的会话里
问了不该问的问题（完全权限桌面会话）；失败文案还误导模型把原因归结为
用户否决。

### 修复

- **完全权限会话改走放行路径（不再问必败 ask）**：`approvalDecision` 门控
  上下文新增 `sandboxMode`。沙箱模式为 `danger-full-access` 时审批门整体让路
  （`graphrag_forget` 同语义——预设描述明确含「敏感操作」），与引擎原生工具
  「full-access 权限**或** approval」约定对齐。**never 沙箱受限时才走 `deny`**，
  文案澄清"宿主显示的 `the user rejected tool` 是自动拒绝、不是用户拒绝"，
  并给出三条出路：
  ① 面板「知识图谱」的「索引」/删除入口（用户直接操作即授权，不经过
  工具审批门）；② 交回允许审批的交互会话（委派场景交回发起会话）；
  ③ `mutatingApproval: "allow"` 预授权后重试。文案含"不要重试本调用"防循环。
- **无人值守预授权逃生门**：`graphrag-tools` 行新增配置
  `mutatingApproval: "ask" | "allow"`（缺省 `ask`）。`allow` 时
  `graphrag_index` / `graphrag_forget` 跳过审批门直接执行（LLM 成本与
  销毁风险由部署方承担），供 headless/自动化部署显式选择。
- **策略探测收敛进适配层**：`src/adapter.ts` 新增 `approvalPolicyOf`
  （鸭子型读取宿主 ApprovalService 的 `overrideOf(session)` 会话覆盖 →
  `config.policy` 服务默认；reflect.get / ctx.get / 属性三读法等价）与
  `sandboxModeOf`（鸭子型读取 `sandboxPolicy.resolve({session}).mode`，
  三读法同款）。服务缺席、形状不符、读取抛错一律返回 undefined → 按
  `ask` / 不参与决策处理，**探测失败永不改变既有行为**（0205 §1 适配层纪律）。

### 回归测试

`tests/tool.test.ts` + `tests/adapter.test.ts` 新增 11 项：

1. `policy=never` → index/forget 均 `deny`：文案含真实原因、"the user
   rejected tool" 澄清、"不是用户拒绝"、面板出路、`mutatingApproval` 出路、
   防重试；
2. `policy=ask` / 策略探测缺省 → 行为不变（照常 `ask`）；
3. `mutatingApproval=allow` → 审批门整体放行（含 never 会话组合）；
4. **完全权限预设（`sandboxMode: danger-full-access`）→ 放行**：含 full+never
   （本缺陷主场景）、full+ask（Auto 预设）、forget 同语义；confined+never
   仍 `deny`、沙箱探测失败+never 仍 `deny`（fail-closed 不回归）；
5. `approvalPolicyOf` 会话覆盖优先于服务默认，reflect/get/prop 三读法等价；
6. 无 session / 无 `overrideOf` 方法 → 只读服务默认；
7. 服务缺席/形状不符/读取抛错/非法策略值 → undefined（按 ask 处理）；
8. `sandboxModeOf`：resolve({session}).mode 三读法等价、无 session 空查询探测、
   三档封闭集可读；
9. `sandboxModeOf` 服务缺席/形状不符/非法模式/resolve 抛错 → undefined。

另有 2 项 `apply` 接线端到端：带 ApprovalService（never）的宿主桩上
`tools/pre-execute` 返回 `deny` 而非 `ask`、`mutatingApproval: "allow"`
时透传放行；**approval never + sandboxPolicy full 的宿主桩上
`tools/pre-execute` 透传 `{kind:'allow'}`**（完全权限不拦截）。

## 兼容性与升级说明

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 交互会话（policy = ask） | 审批卡 → 用户确认 | 不变 |
| **桌面「完全权限」预设（sandbox full + never）** | 必败 ask，误报 "the user rejected tool" | **直接放行（预设即预授权）** |
| 委派子代理 / headless（never，沙箱受限） | 必败 ask，误报 "the user rejected tool" | `deny` + 真实原因 + 可操作出路 |
| never + `mutatingApproval: allow` | 必败 ask | 直接执行（部署方预授权） |
| 宿主无 ApprovalService / SandboxPolicy / 探测失败 | 宿主按自身语义拒绝 | 不变（照常 ask） |

- `mutatingApproval` 缺省 `ask`：**受限会话没有任何行为放宽**，只是失败从
  "误报用户拒绝"变为"准确拒绝 + 出路"；放宽仅发生在「完全权限」预设——
  那是用户在权限设置里显式选择的预授权语义。
- 期望 agent 在无人值守会话直接建库索引的部署，在 `graphrag-tools` 行加
  `mutatingApproval: "allow"` 即可；风险面（LLM 成本、graphrag_forget 销毁）
  自担。
