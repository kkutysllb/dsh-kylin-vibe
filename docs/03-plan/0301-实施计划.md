**M1 出口评审结论（2026-10-02）**

三配置终版（40 题冻结集，oracle 抽取）：

| 指标 | flat-bm25 | graph-local | graph-full | 门槛判定 |
|---|---|---|---|---|
| local entityHit@5 / relationRecall | 1.000 / 1.000 | 1.000 / 1.000 | 1.000 / 1.000 | 门槛 1 ❌ |
| global coverage | 0.875 | 0.900 | **0.9417** | 门槛 2 ❌ |
| traversal P / R / F1 | 0.567 / 0.211 / 0.256 | 0.945 / 1.000 / **0.971** | 0.945 / 1.000 / **0.971** | 门槛 3 ✅ |

- **门槛 3 通过且优势压倒**（F1 0.256 → 0.971）：多跳影响分析——图谱的核心卖点拿到实证。
- **门槛 1/2 未过，根因是门槛定义的结构性缺陷而非实现缺陷**：门槛 1 要求基线(1.0)+15%，超过指标上限 1.0，不可达；门槛 2 要求 0.875×1.2=1.05，同样超过 coverage 上限 1.0。两者在小而精语料上基线已贴天花板（W1 已预警）。
- **处理决定（回炉方案，M2 期间并行执行，不阻塞 M2）**：0206 §3.2 门槛修订为 v2——①门槛 1 改为排序敏感指标（local MRR@5：golden 实体在证据包中的排名质量）+ 增设 5 道多跳无共现 local 题（questions v2，走 changelog 版本化）；②门槛 2 改为绝对差（global coverage ≥ 基线 + 0.05）并计入社区代表覆盖面回归。修订随 questions v2 一起评审冻结。
- **M1 判定：代码完备出口（有条件通过）**。核心引擎六模块（chunker/lexical/graphstore/extractor/lpa+ppr+search/scanner+ingest）全部落地且有测试护栏；两道门槛的失败已归因到评测设计并排期回炉。

**M1 规模估计：~3.5 周（含 1 周缓冲）；交付物：核心库 + 评测集 + 三张记分卡**

**W3 宿主暴露缺陷记录（0.2.0-rc.2 实测）**：
1. seam effect 写法错误：把卸载逻辑写进 setup（cordis `effect(setup)` 立即执行 setup、返回值才是 disposer）→ 挂载即卸载，冒烟桩抓出；

3. **属性直赋挂服务被禁**：`cannot set property "graphrag" without provide` → 必须经 `ctx.reflect.provide(name, value)`；
4. **未 inject 的服务属性访问抛错**：`cannot get property "llm" without inject` → 必须 `ctx.reflect.get('llm', false)` 非严格读取（同时保留无 llm 降级矩阵）；连带把 completer 改为调用时惰性解析（apply 早于 llm provide）；
5. `ctx.agents.on` 不存在 → agent 生命周期事件在 `ctx.on('agent/created'|'agent/disposed')`；
6. 宿主对 error 信封同样调用 `output.render` → render 必须对非证据包形状设防。
另：`lastIndexAt` meta 读写键不一致（恒 null）已在收尾修复；`permission-presets` 覆盖行的正确 id 是 `permission`（base 行），预设覆盖对 headless 全局自动拒绝不生效（运行时层面禁用审批提示，非插件可解）。
