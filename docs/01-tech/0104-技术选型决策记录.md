# 0104 · 技术选型决策记录（ADR）

- 日期：2026-10-01
- 状态：定稿
- 约定：每条决策含【背景 → 备选 → 决策 → 理由 → 复审条件】。编号 `ADR-n`，后续新决策追加。

## ADR-1 语言与运行时：TypeScript + Node 内置能力优先

- **背景**：核心引擎需在 dsh 与 QiLin 宿主进程内运行，且要能被宿主工具面直接调用。
- **备选**：Rust/Python 侧车进程（IPC）；WASM；纯 TS。
- **决策**：纯 TypeScript，只用 Node 内置模块 + 极少量纯 JS 依赖。
- **理由**：两个宿主都是 Node/TS/Cordis，进程内调用零 IPC 成本；automation 插件已验证零原生依赖的分发路径最稳（安装期零构建、pnpm 无需构建许可）。
- **复审**：若抽取吞吐成为瓶颈（单文件索引 > 分钟级），考虑 worker_threads 并行（仍在进程内）。

## ADR-2 图存储：`node:sqlite`（单文件 SQLite）

- **背景**：需要持久化实体/关系/社区/chunk，支持 FTS 全文与事务性增量更新。
- **备选**：better-sqlite3（原生编译）；纯 JSON 文件；LevelDB；外部图数据库（Neo4j）。
- **决策**：`node:sqlite`，单库文件 `graphrag.db`，FTS5 虚表做词法召回。
- **理由**：Node ≥22.13 内置、两宿主基线 Node ≥22.19 满足；**零原生编译**——双引擎分发中原生模块是最大坑（不同 Node ABI/不同宿主安装路径）；SQLite 事务天然匹配"文件级 checkpoint"的增量语义；graph-memory 同路线已验证规模可行。
- **复审**：若 `node:sqlite` 在某宿主 Node 构建中被裁剪（能力探测失败），降级路径为 JSON 快照 + 内存索引（GraphStore 接口隔离，见 0202）。

## ADR-3 LLM 访问：宿主 `ctx.llm`，插件零凭据

- **背景**：实体抽取与社区摘要需要 LLM；用户已在宿主配置 provider。
- **备选**：插件自带 API key 配置直连 provider；要求用户配置独立 embedding 服务；走宿主 llm 服务。
- **决策**：全部 LLM 调用走 `ctx.llm.stream()`（inject `llm`），抽取用宿主当前模型，插件不持有任何凭据。
- **理由**：dsh-ragflow 证明凭据治理走宿主 credential 服务是正解；DSH-RAG 的"离线 BM25 可用"启示我们**词法检索路径零 LLM 依赖**（无 provider 也能用 status/graph/traversal）；失败码（`RATE_LIMIT` 等）路由统一。
- **复审**：若宿主 provider 不支持结构化 JSON 输出稳定性差，在抽取层加输出修复重试（本地逻辑，不换通道）。

## ADR-4 社区检测：LPA（标签传播），单层

- **背景**：global 检索需要社区划分。
- **备选**：Leiden（分层）；Louvain；LPA。
- **决策**：LPA 单层，纯本地迭代实现（<200 行 TS）。
- **理由**：近似线性复杂度、零 LLM 成本、实现简单可测；社区只用于导航与摘要分桶，不追求划分最优性（graph-memory 验证）；分层留存储字段不实现。
- **复审**：若 global 模式评测显示单层粒度不够，升级 Leiden 分层（存储已预留 `level` 字段）。

## ADR-5 查询排序：PPR + FTS5/BM25 基线，嵌入向量后置

- **背景**：local 检索需要"查询→实体→邻域"的排序机制。
- **备选**：向量 Top-K（需 embedding 服务）；纯词法；PPR+词法混合。
- **决策**：一期 = FS5/BM25 种子命中 + PPR 扩散排序（全本地、零 LLM、零凭据）；向量检索不进一期。
- **理由**：`ctx.llm` 未验证统一暴露 embedding；DSH-RAG 的冻结评测纪律——复杂度只有赢过基线才进主干；graph-memory 的 FTS 兜底+可选 embedding 分层降级架构可直接借用。
- **复审**：冻结评测集（0206）建立后，若向量基线显著优于词法基线（hit@5 提升 ≥15%），二期加 embedding provider 缝。

## ADR-6 索引增量：内容 hash + 文件级 checkpoint + 隔离区

- **背景**：LLM 抽取成本高，全量重建不可接受。
- **决策**：文件内容 hash 变更检测；每文件处理状态（pending/extracted/merged/failed-quarantined）持久化，断点续跑；抽取解析失败进隔离区不污染主图；社区摘要按社区指纹缓存，成员变化超阈值才重算。
- **理由**：直接继承 DSH-RAG 已验证的增量机制 + graph-memory 的隔离区机制（见 0101 §5）。
- **复审**：无（机制型决策）。

## ADR-7 插件打包：三角色（seam/provider/consumer）单包多入口

- **背景**：需要在保持可替换性的同时最小化分发复杂度。
- **备选**：单一大插件；多包 monorepo；三角色单包多入口。
- **决策**：学 dsh-ragflow——一个 npm 包，`cordis.patch.yml` 按 seam（`ctx.graphrag`）/ provider（本地引擎）/ consumer（工具、配置页）拆行注册，角色间只依赖 seam。
- **理由**：换引擎（未来接 RAGFlow/Neo4j provider）= 换 patch 一行；关工具面 = disable 一行；与 Cordis 组合理念同构。
- **复审**：无。

## ADR-8 工具入口：agent 显式调用，v1 不做上下文接管

- **背景**：需求是"agent 执行任务时调用以推理"，与 graph-memory 的"自动接管历史"是两种产品形态。
- **决策**：只提供模型可调用工具（`graphrag_query` / `graphrag_graph` / `graphrag_index` / `graphrag_status` / `graphrag_forget`）+ systemPrompt 能力公告；不自动改写模型可见历史。
- **理由**：显式调用可观测、可审计、可审批（index/forget 走人工审批门）；自动接管与"任务推理"场景错配。
- **复审**：二期若高频用户要求记忆化，另立记忆插件（数据模型不同，见 0102 §5）。

## ADR-9 索引范围默认值：显式授权目录，默认不索引整个工作区

- **背景**：待定项之一（前期讨论遗留）。
- **决策**：默认零授权（不索引任何东西）；用户通过配置/工具显式授权目录（`roots`），hidden/凭据模式文件排除，realpath 规范化。
- **理由**：LLM 抽取有真实成本，静默全仓索引 = 静默花钱，违背 DSH-RAG 已验证的安全模型；显式授权让审批与成本可预期。
- **复审**：若评测/使用数据显示授权摩擦过大，提供"工作区白名单快捷授权"配置项（仍显式）。

## ADR-10 Web 面板：延后到 M3，可选角色

- **背景**：待定项之二（前期讨论遗留）。
- **决策**：一二期纯 agent 工具面 + 环境变量/YAML 配置；M3 视需要加只读面板（图可视化/索引进度），作为可 disable 的独立 consumer 行。
- **理由**：面板是 client inject 面（automation 兼容表中标为中等风险），不为核心路径挡路；工具面自身已闭环。
- **复审**：M3 开始前按用户反馈定。

## ADR-11 文档解析范围（一期）：文本类优先

- **背景**：语料可能是代码、Markdown、配置，也可能是 PDF/DOCX。
- **决策**：一期支持 UTF-8 文本族（代码/MD/TXT/JSON/YAML/CSV，按扩展名+编码探测）；PDF/DOCX/PPTX 解析二期（纯 JS 解析器依赖较重，且编码场景密度低）。
- **理由**：目标场景是编码 agent 的任务推理，语料主体是文本；控制一期依赖面。
- **复审**：二期按需求加，走独立 parser 接口（0203）。

## ADR-12（修订 ADR-10）：Web 面板从"可选延后"升级为"必做核心"

- **背景**：M2 完成后用户质询"用户使用入口在哪、任务怎么指定知识库、准确性怎么验证"——三者均指向同一缺口：纯 agent 工具入口对"构建知识库"的产品目标是不可用的。
- **决策**：撤销 ADR-10 的"面板后置"；按 0207 落地多知识库（KB 一等实体）+ Web 管理面板（KB 管理/索引进度/图谱浏览/抽样审查四页）+ 用户侧准确性验证（抽样精确率 + 体检报告）。
- **理由**：建库成本与进度、任务→库绑定、可信度评估都需要人直接可见可操作的面；agent 工具面保留为"模型侧入口"，两者互补而非替代。
- **复审**：QiLin client 面差异过大时，QiLin 侧面板可后置（headless 工具面保底），见 0207 §5。
