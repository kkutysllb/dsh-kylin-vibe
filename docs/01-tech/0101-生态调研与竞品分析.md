# 0101 · dsh 插件生态调研与竞品分析

- 日期：2026-10-01
- 状态：定稿（作为立项依据）
- 调研目标：为 `dsh-kylin-vibe`（dsh + QiLin 双引擎 GraphRAG 插件）寻找可借鉴的开源实现，确认生态空白点，提炼设计输入

## 1. 调研范围与方法

调研对象为 DeepSeek Harness（dsh）插件生态中"知识库 / RAG / 知识图谱 / 记忆"方向的开源项目。方法：

1. 以 `dsh-plugin` GitHub topic、dsh 官方 Discussions、awesome-dsh-plugin 精选列表为入口扫描；
2. 用 GitHub API 核实星数与活跃度（本文数据截至 2026-10-01）；
3. 对入围项目逐个通读 README 与架构说明，按"与我们需求的贴近度 + 工程质量"做深入分析。

我们的需求基准：**面向文档/工作区语料的 GraphRAG（实体关系抽取 + 社区 + local/global 检索 + 图遍历），以 agent 工具形式暴露供任务推理调用，同时兼容 dsh 与 QiLin 双引擎。**

## 3. 深入分析

### 3.1 adoresever/graph-memory —— 633★，图谱记忆插件的事实标准

**定位**：从对话历史抽取 SPO（主谓宾）结构化三元组构建知识图谱，跨会话记忆复用，并用"上下文接管"（context takeover）以图谱压缩模型可见历史，首轮请求 token 约 −80%。2026 年 4 月受邀在清华大学讨论会发布。

**技术要点**：

- 图构建：每轮对话结束后做**一次**辅助 LLM 调用完成三元组抽取（成本纪律：抽取调用量与对话轮数线性、与图规模无关）；实体合并消除别名；社区检测用 LPA（标签传播，纯本地计算，无 LLM 参与）。
- 查询：查询时 Personalized PageRank（PPR）排序，种子来自查询词命中的实体；SQLite 存储，FTS5 全文兜底，embedding 可选（OpenAI 兼容接口，环境变量配置，未配置则降级）。
- 质量防线：解析失败或无效抽取进**隔离区**（quarantine），不污染主图，可修复后重放。
- 工具面：6 个 agent 工具（`gm_status` / `gm_search` / `gm_record` / `gm_stats` / `gm_maintain` / `gm_retry_extraction`），透明可观测。
- 多宿主：**同一核心 + 每宿主薄适配层**（DSH 原生 Cordis 适配器 + OpenClaw Context Engine 适配器）。
- 质量与约束：138/138 测试通过，MIT，Node 22.13+，不需要 fork DSH。

**关键设计原则（值得我们直接继承）**："**图谱是导航层，不是证据源**"——摘要/三元组/社区只用于导航与路由，回答引用必须回到原文精确位置。这让它敢于做激进的上下文压缩而不失可信。

**与需求的差距**：抽取对象是对话历史而非文档/工作区文件；没有面向语料的 local/global 双模式检索（Microsoft GraphRAG 式社区摘要全局问答）；不做代码/文档任务推理场景。

### 3.2 imkelt/DSH-RAG —— 工程质量最高的本地文档知识库

**定位**：把显式授权的本地文件夹变成命名知识库，增量同步，混合检索，证据卡片带精确来源位置。

**技术要点**：

- 检索：离线多语言 BM25（无 API key 即可用）+ 可选 SiliconFlow embedding + 本地向量 + RRF 融合 + 可选重排；文档解析覆盖 PDF/DOCX/PPTX/MD/TXT。
- 交互模型：`/rag` 斜杠命令做**会话级**检索，检索在模型作答之前完成（刻意设计为"非模型决定"的显式检索），支持 @知识库 单轮覆盖。
- 增量索引：文件级 checkpoint、可取消、watcher 防抖、崩溃后恢复扫描。
- 安全模型：realpath 规范化防路径逃逸；排除隐藏目录与凭据类文件；API key 存 OS 凭据库不落盘；数据放 `$DSH_HOME/dsh-rag/`。
- 方法论亮点：**冻结评测集**驱动迭代——v0.1 因为"AI 生成的文档上下文摘要未提升冻结评测分数"而砍掉了该特性。
- 约束：Node ^22.19 或 >=24，基于 DSH 0.1.1-rc.2 验证。

**与需求的差距**：完全没有知识图谱（纯词法+向量平铺检索）；检索入口是斜杠命令而非 agent 自主调用的工具；不支持图遍历/多跳推理。

**特别值得继承**：增量索引机制（对我们更重要——LLM 抽取式索引比纯文本索引贵一个数量级，断点续跑是生死线）；安全模型；冻结评测的方法论纪律。

### 3.3 staff-os/dsh-ragflow —— 三角色架构范本 + 外部引擎桥接

**定位**：桥接外部 RAGFlow 服务（RAGFlow 自身带 GraphRAG 模式），给 agent 一个 `ragflow_retrieve` 工具，返回 chunk 与相似度分数。

**技术要点**：

- **三角色能力模式**（官方 practice 文档推荐模式）：一个包、四个插件入口——
  - Service Definition（seam）：拥有 `ctx.ragflow`，provider 注册表、顺序无关选择、`maxChunks` 上限执行；
  - Service Provider：HTTP 实现（`POST /api/v1/retrieval`、凭据解析、chunk 归一化）；
  - Consumer ×2：模型向工具（schema、提示引导、chunk 上限、呈现）+ 人员向配置页（同一批配置与凭据缝）。
  - Provider 与 Consumer 只依赖 seam、互不依赖；换后端 = 替换 patch 中一行。
- 配置分层：schema 默认 → `cordis.patch.yml` 行 → `~/.dsh/settings.yaml` 用户保存段 → 环境变量；凭据走 credential 服务，永不进配置文件；配置页仅 loopback。
- 分发：`lib/` 直接提交，安装时不跑构建，pnpm 无需构建许可。
- 前提：需要自部署 RAGFlow 实例 + API key + 已解析的数据集。

**与需求的差距**：外部引擎部署负担重，违背本地优先；agent 只拿到检索 chunk，引擎内部图谱对 agent 不可见（无多跳遍历）；不做本地语料索引。

**特别值得继承**：三角色拆分就是 Cordis 原生思路的标准答案；配置与凭据治理范式；"seam 保留替换外部引擎可能性"的架构远见。

## 4. 生态空白点结论

三个项目拼图之后，空白正好是我们的需求：

| 能力维度 | graph-memory | DSH-RAG | dsh-ragflow | 我们的目标 |
|---|---|---|---|---|
| 文档/工作区语料 ingest | ✗（对话历史） | ✓ 增量 | ✓（外部） | ✓ 本地增量 |
| LLM 实体/关系抽取 | ✓（对话） | ✗ | 外部 | ✓（语料） |
| 社区检测 + 摘要 | ✓ LPA（无摘要问答） | ✗ | 外部 | ✓ LPA + 社区摘要 |
| local/global 双模式检索 | ✗ | ✗（平铺混合） | 外部 | ✓ |
| 图遍历（多跳） | 部分（PPR 隐式） | ✗ | ✗ | ✓ 显式工具 |
| agent 工具入口 | ✓ 6 工具 | ✗ 斜杠命令 | ✓ 1 工具 | ✓ 多工具 |
| 双引擎（dsh+QiLin） | ✓（DSH+OpenClaw） | ✗ | ✗ | ✓ |
| 本地优先（无外部服务） | ✓ | ✓ | ✗ | ✓ |

**没有任何一个现有 dsh 插件同时做到"文档语料 GraphRAG + agent 工具化 + 双引擎"。** 项目定位成立。

## 5. 对本项目的设计输入汇总

| 来源 | 继承内容 |
|---|---|
| graph-memory | 双宿主适配器分层；SPO 抽取 + 实体合并 + LPA + PPR 的核心组合；抽取成本纪律（每 chunk 一次调用）；隔离区机制；"图谱导航、原文举证"原则；透明状态工具 |
| DSH-RAG | 文件级 checkpoint 增量索引 + 可取消 + 防抖 + 恢复扫描；显式授权目录 + realpath + 隐藏/凭据排除 + 凭据库的安全模型；证据卡片（精确来源位置）；冻结评测集纪律 |
| dsh-ragflow | 三角色（seam/provider/consumer）打包；配置分层与凭据治理；`lib/` 提交免安装构建；为未来外部引擎 provider 预留缝 |
