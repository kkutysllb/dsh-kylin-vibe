# 0202 · 数据模型与存储设计

- 日期：2026-10-01
- 状态：定稿（实施基准）
- 上游依据：0201（总体架构）、ADR-2（node:sqlite）、ADR-6（增量与隔离区）

## 1. 存储总览

- 每个工作区（`cwd`）一个独立存储目录：`<dataDir>/workspaces/<sha256(cwd)[0:16]>/graphrag.db`；`dataDir` 由适配层 `resolveDataDir(ctx)` 决定（dsh：`$DSH_HOME/graphrag`，回落 `~/.dsh/graphrag`；QiLin 按宿主 home 约定，M3 落定）。
- 单文件 SQLite（`node:sqlite`），WAL 模式（读写并发），`foreign_keys = ON`，`journal_mode = WAL`，`busy_timeout = 5000`。
- 库内版本表 `meta` 驱动迁移（见 §5）。
- FTS5 虚表承担词法召回（chunk 原文 + 实体名/别名）。

## 2. 领域模型（ER 描述）

```
source 1──n chunk 1──n mention n──1 entity
entity n──n relation（边，经 mention 聚合而来）
entity n──1 community（LPA 划分，单层；level 字段预留）
community 1──1 community_summary（LLM 摘要，带指纹缓存）
extraction_batch（抽取批次/checkpoint 状态机）
quarantine（隔离区：失败抽取原文与错误）
```

## 3. 表结构（DDL 草案）

```sql
-- 元信息与版本
CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
--   约定键：schema_version / created_at / last_index_at / graph_fingerprint

-- 源文件（授权 roots 下的已收录文件）
CREATE TABLE source (
  id          INTEGER PRIMARY KEY,
  path        TEXT NOT NULL UNIQUE,        -- 相对工作区根的规范路径
  abs_path    TEXT NOT NULL,               -- realpath 结果，防逃逸审计用
  content_hash TEXT NOT NULL,              -- sha256，变更检测
  size_bytes  INTEGER NOT NULL,
  mtime_ms    INTEGER NOT NULL,
  state       TEXT NOT NULL DEFAULT 'pending',
              -- pending | chunked | extracting | extracted | merged | failed | quarantined | deleted
  error       TEXT
);

-- 文本块
CREATE TABLE chunk (
  id          INTEGER PRIMARY KEY,
  source_id   INTEGER NOT NULL REFERENCES source(id) ON DELETE CASCADE,
  ordinal     INTEGER NOT NULL,            -- 文件内序号
  start_line  INTEGER NOT NULL, end_line INTEGER NOT NULL,
  start_col   INTEGER NOT NULL, end_col   INTEGER NOT NULL,   -- 举证精确定位
  text        TEXT NOT NULL,
  token_est   INTEGER NOT NULL,
  UNIQUE(source_id, ordinal)
);

-- 实体（已归一）
CREATE TABLE entity (
  id          INTEGER PRIMARY KEY,
  norm_name   TEXT NOT NULL UNIQUE,        -- 规范化名（小写/去符号）
  name        TEXT NOT NULL,               -- 展示名（首见原名）
  type        TEXT NOT NULL,               -- module|function|class|concept|config|dependency|...
  description TEXT,                        -- 合并后的描述（二手信息）
  community_id INTEGER REFERENCES community(id) ON DELETE SET NULL,
  degree      INTEGER NOT NULL DEFAULT 0   -- 冗余度数，遍历排序用
);
CREATE TABLE entity_alias (
  entity_id INTEGER NOT NULL REFERENCES entity(id) ON DELETE CASCADE,
  alias     TEXT NOT NULL,
  PRIMARY KEY (entity_id, alias)
);

-- 关系边
CREATE TABLE relation (
  id          INTEGER PRIMARY KEY,
  src_id      INTEGER NOT NULL REFERENCES entity(id) ON DELETE CASCADE,
  dst_id      INTEGER NOT NULL REFERENCES entity(id) ON DELETE CASCADE,
  type        TEXT NOT NULL,               -- uses|calls|imports|depends_on|defines|relates_to|...
  weight      INTEGER NOT NULL DEFAULT 1,  -- mention 聚合计数
  description TEXT,
  confidence  REAL NOT NULL DEFAULT 0.5,   -- 抽取置信度聚合
  UNIQUE(src_id, dst_id, type)
);
CREATE INDEX idx_relation_src ON relation(src_id);
CREATE INDEX idx_relation_dst ON relation(dst_id);   -- 反向遍历（影响分析）

-- 实体提及（chunk 内出现，举证的桥梁）
CREATE TABLE mention (
  id          INTEGER PRIMARY KEY,
  chunk_id    INTEGER NOT NULL REFERENCES chunk(id) ON DELETE CASCADE,
  entity_id   INTEGER NOT NULL REFERENCES entity(id) ON DELETE CASCADE,
  span_start  INTEGER NOT NULL, span_end INTEGER NOT NULL  -- chunk 内字符区间
);
CREATE INDEX idx_mention_entity ON mention(entity_id);
CREATE INDEX idx_mention_chunk ON mention(chunk_id);

-- 社区（LPA 单层；level 预留分层）
CREATE TABLE community (
  id          INTEGER PRIMARY KEY,
  level       INTEGER NOT NULL DEFAULT 0,
  label       INTEGER NOT NULL,            -- LPA 收敛后的标签
  fingerprint TEXT NOT NULL,               -- 成员集合 hash，摘要缓存失效判断
  member_count INTEGER NOT NULL
);

-- 社区摘要（global 检索语料）
CREATE TABLE community_summary (
  community_id INTEGER PRIMARY KEY REFERENCES community(id) ON DELETE CASCADE,
  summary      TEXT NOT NULL,              -- LLM 生成，标记二手信息
  entities_top TEXT NOT NULL,              -- 代表实体（度数 top-N 名单，JSON）
  generated_at INTEGER NOT NULL,
  fingerprint_at TEXT NOT NULL             -- 生成时的社区指纹
);

-- 抽取批次（checkpoint 状态机）
CREATE TABLE extraction_batch (
  id          INTEGER PRIMARY KEY,
  started_at  INTEGER NOT NULL,
  finished_at INTEGER,
  status      TEXT NOT NULL DEFAULT 'running',  -- running|done|aborted|failed
  llm_calls   INTEGER NOT NULL DEFAULT 0,
  tokens_in   INTEGER NOT NULL DEFAULT 0,
  tokens_out  INTEGER NOT NULL DEFAULT 0,
  files_total INTEGER NOT NULL DEFAULT 0,
  files_done  INTEGER NOT NULL DEFAULT 0
);

-- 隔离区（失败抽取，不污染主图）
CREATE TABLE quarantine (
  id          INTEGER PRIMARY KEY,
  chunk_id    INTEGER REFERENCES chunk(id) ON DELETE SET NULL,
  raw_input   TEXT NOT NULL,               -- 送入 LLM 的 chunk 文本
  raw_output  TEXT,                        -- LLM 原始返回（截断存储）
  error_code  TEXT NOT NULL,               -- PARSE_FAILED|LLM_ERROR|SCHEMA_INVALID
  error_detail TEXT,
  created_at  INTEGER NOT NULL,
  resolved    INTEGER NOT NULL DEFAULT 0   -- 0 待处理；1 已重放/丢弃
);

-- 词法召回（FTS5）
CREATE VIRTUAL TABLE chunk_fts USING fts5(
  text, source_path UNINDEXED, tokenize='trigram'  -- 多语言/代码友好
);
CREATE VIRTUAL TABLE entity_fts USING fts5(name, tokenize='trigram');
```

设计说明：

- **mention 是举证桥梁**：实体/关系 → mention → chunk → 行列号，保证"图谱导航、原文举证"可机械执行（0204 证据包据此组装）。
- **`relation` 双向索引**：`graphrag_graph` 的方向遍历（影响分析走 `idx_relation_dst` 反查）。
- **`degree`/`entities_top` 冗余**：避免查询期全图扫描，索引时维护。
- **trigram 分词器**：对代码标识符（`getUserById`）与中文都友好，无需外置分词；比 unicode61 的 substring 匹配召回好。
- **`entity_fts` 含别名**：写入时实体名 + 全部别名合并进 FTS 行（别名表仍存规范数据）。

## 4. GraphStore 接口（存储抽象）

核心库不直接碰 SQL，面向接口编程（ADR-2 的降级路径依赖此缝）：

```ts
export interface GraphStore {
  // source/chunk 生命周期
  upsertSource(s: SourceInput): Promise<SourceRow>
  diffDirty(roots: string[], excludes: Matcher): Promise<DirtyFile[]>     // hash 对比
  replaceChunks(sourceId: number, chunks: ChunkInput[]): Promise<void>
  // 图写入（批次事务）
  applyExtraction(batch: ExtractionDelta): Promise<void>   // mention+entity upsert+relation 聚合，单事务
  // 图读取
  findEntitiesByLexical(q: string, limit: number): Promise<EntityHit[]>
  getEntity(normName: string): Promise<EntityRow | null>
  neighbors(id: number, dir: 'out'|'in'|'both', types?: string[]): Promise<EdgeRow[]>
  bfs(startIds: number[], hops: number, dir, types, budget): Promise<SubgraphRows>
  chunksForEntities(ids: number[], limitPerEntity: number): Promise<ChunkRef[]>
  // 社区
  recomputeCommunities(): Promise<CommunityDelta>          // LPA 写回 + 指纹
  staleCommunities(threshold: number): Promise<CommunityRow[]>
  putSummary(c: CommunitySummaryInput): Promise<void>
  allSummaries(): Promise<SummaryRow[]>
  // 治理
  forget(target: ForgetTarget): Promise<ForgetReport>
  quarantine: QuarantineStore
  checkpoint: CheckpointStore                              // source.state / extraction_batch
}
```

事务边界约定：**一个文件的 `applyExtraction` 是一个事务**；`recomputeCommunities` 一个事务；崩溃恢复后以 `source.state` 为准重入。

## 5. 迁移与兼容

- `meta.schema_version` 起始 `1`；每次结构变更 +1 并在 `migrations/` 下追加幂等迁移函数（`BEGIN IMMEDIATE` 内执行）；
- 打不开/版本过新 → 明确错误码 `SCHEMA_FUTURE`，不静默重建（数据是花过 LLM 成本的）；
- `graphrag_forget('graph')` 是唯一全量重置路径（走审批门）。

## 6. 容量预估与性能预算

以中型仓库（2000 文件、约 4000 chunk、1.5 万实体、4 万边）为设计点：

| 操作 | 预算 | 依据 |
|---|---|---|
| `diffDirty`（全量 hash 对比） | < 1s | 仅读 meta 表 + 文件 stat |
| local 查询（FTS 种子 + PPR 迭代 20 轮） | < 200ms | PPR 稀疏实现，图中 MPI 通常 ≤ 20 |
| traversal（3 跳，度数截断） | < 100ms | BFS + degree 排序剪枝，节点预算 500 |
| LPA（1.5 万节点） | < 2s | 线性迭代，阈值收敛 |
| 索引 1 个变更文件 | 1 次 LLM 调用 + <50ms 本地 | 增量稳态 |
| 库文件体积 | < 200MB | chunk 原文 + FTS 索引为主体 |

超预算时的降级：`bfs` 带 `budget` 硬上限（返回截断标记）；PPR 迭代轮数可配；FTS 命中数 limit。

## 7. 安全与隐私（存储面）

- 授权 roots 之外路径一律拒绝（realpath 后前缀匹配，学 DSH-RAG）；
- 默认排除：隐藏目录（`.git`/`.env*`/`*credentials*`/`*secret*`/`*.pem` 等，模式表可配）；
- 库文件权限 0600；`abs_path` 仅本地审计，不进任何 LLM 输入——送入 LLM 的只有 chunk 文本（脱敏由排除规则前置保证）；
- 工作区目录名用 hash 而非路径明文，避免路径中的敏感信息落盘。
