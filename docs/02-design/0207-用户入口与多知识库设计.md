# 0207 · 用户入口与多知识库设计（M3 核心范围修订）

- 日期：2026-10-02
- 状态：定稿（取代 ADR-10"面板延后可选"的判断——用户入口是产品核心，不是可选件）
- 背景用户质询：① 用户使用入口在哪；② 任务怎么指定用哪个知识库；③ 知识库准确性怎么验证

## 1. 问题定义（当前版本的缺口）

| 缺口 | 现状 | 后果 |
|---|---|---|
| 无用户入口 | 用户只能靠"让 agent 调 graphrag_index + 审批"建库 | 建库动机、成本、进度对用户全部黑箱 |
| 单一隐式知识库 | 一工作区(cwd)一图，无名字、无选择 | 多项目/多语料场景无法区分"哪份资料给哪个任务" |
| 准确性不可验证 | 证据引用只在工具返回里，用户看不到 | 用户无法判断图谱可信度，不敢用结论 |

## 2. 多知识库：KB 升为一等实体

### 2.1 数据模型

```ts
interface KnowledgeBase {
  id: string                       // slug（存储目录名）
  name: string                     // 用户可读名，唯一（"星帆商城文档"、"atlas 代码库"）
  roots: string[]                  // 授权目录（realpath 校验）
  description?: string
  createdAt: number
  lastIndexedAt: number | null
}
```

- 注册表：`<dataDir>/kbs.json`（Web/配置双写入口的持久层）；每 KB 独立存储 `dataDir/kbs/<id>/graphrag.db`
- **迁移**：现 `workspaces/<cwdhash>/` 单库模型映射为迁移时的默认 KB（name = 工作区目录名），一次迁移写入 kbs.json
- 配置双入口：patch 行静态声明 `kbs: [{name, roots, description}]`（启动时 merge，name 冲突以补丁为准）+ Web 动态创建（写 kbs.json）

### 2.2 Seam 契约扩展（GraphRagProvider v2）

```ts
listKbs(): KnowledgeBase[]
createKb(input: { name, roots, description? }): KnowledgeBase     // Web 主用
updateKb(id, patch: { name?, roots?, description? }): KnowledgeBase
deleteKb(id): ForgetReport                                          // 审批门
// 既有五方法全部加显式 KB 定位：byName | byId；解析失败报 AVAILABLE_KBS 候选
status(target?: KbRef): IndexStatus
index(target: KbRef, opts, signal): IndexReport
query(target: KbRef | undefined, q): EvidencePack                  // undefined = 默认解析
traverse(target: KbRef | undefined, t): Subgraph
forget(kbId, inner: ForgetTarget): ForgetReport
```

默认解析顺序（query/traverse 未传 kb 时）：① cwd 落在某 KB roots 内且唯一 → 该 KB；② 恰有一个 KB → 它；③ 多候选 → 返回候选名单（错误码 `KB_AMBIGUOUS`），模型/用户二选一。

### 2.3 工具契约扩展（0204 v2）

- 五工具全部增加可选 `kb` 参数（KB 名称字符串）；`graphrag_status` 不传 = 列出全部 KB 概览
- `graphrag_index` 增加语义：传不存在的 kb 名 + `create: true` + `roots` = 建库并索引（仍走审批，审批卡展示"新建知识库 X：目录 Y，预计 N 次调用"）
- 公告段更新：列出现有 KB 名单，教学"任务涉及哪份语料就传哪个 kb"

### 2.4 任务→知识库绑定（回答质询②）

| 绑定方式 | 机制 | 场景 |
|---|---|---|
| 显式指定 | agent 工具调用带 `kb: "atlas 代码库"` | 任务推理时模型按任务语义选择（公告教学 + KB 名单在 status 里可查） |
| 工作区默认 | cwd 命中某 KB roots → 自动选中 | 日常编码：打开哪个项目就用哪个库 |
| 唯一库默认 | 仅一个 KB 时自动选中 | 单库小团队零配置 |
| 任务模板 | automation 任务的 prompt 模板里写明 kb 名 | 定时任务绑定固定资料库（二期与 automation 联动） |

## 3. 用户入口：Web 管理面板（dsh 先行，对齐 automation client 模式）

四页（复用 automation 已验证的 client inject 面 + RPC 通道；面板仅 loopback，学 dsh-ragflow）：

### 3.1 知识库管理页（回答质询①）

- KB 卡片列表：名称 / roots / 描述 / 规模（实体·关系·社区）/ 最后索引时间 / 健康度灯（绿=新鲜 黄=有陈旧 红=有隔离/未建）
- 新建/编辑表单：名称 + 授权目录（多目录）+ 描述；保存即写 kbs.json（动态 KB）
- 每 KB 操作：**索引（含 dry-run 成本预估卡）** / 取消 / 遗忘（二次确认）/ 删除 KB
- 静态配置声明的 KB 显示为"配置托管"（只读，改配置需改 patch）

### 3.2 索引进度页

- 实时进度：filesDone/total、当前文件、阶段（分块/抽取/归并/社区/摘要）、LLM 调用数与 token 计数、隔离区增量
- 机制：provider 暴露 `progress(cwd, kbId)` 快照，RPC 轮询（1s）；复用 ingest 的 onProgress 回调

### 3.3 图谱浏览页

- 实体搜索（FTS 前缀）→ 实体卡（类型/描述/社区/度数）
- 邻居表（方向/关系类型/权重）→ 点击边 = 展开源 chunk 原文（行列号 + 文件路径，可跳转）
- 社区列表 → 社区摘要 + 成员实体

## 4. 准确性验证：三层防线 + 用户抽样

### 4.1 分层（构建期/检索期/验收期）

| 层 | 机制 | 状态 |
|---|---|---|
| 构建期 | 置信度阈值过滤、封闭类型集、解析失败进隔离区、**隔离率指标** | 已有（M1） |
| 检索期 | 一切结论强制回原文（chunks 带 path+lines）；社区摘要标"二手" | 已有（M1/M2） |
| 验收期 | **用户抽样审查** + 每库精确率指标 + 体检报告 | 本期新增 |
| 开发期 | 冻结评测集（40 题门槛）——开发侧质量门，不暴露给用户 | 已有（0206） |

### 4.2 抽样审查（核心新增）

- 入口：KB 详情页"准确性"标签 → "抽查 20 条"
- 交互：随机抽样该 KB 的关系（按 confidence 分层抽样：低置信优先）——左侧三元组卡片，右侧源 chunk 原文高亮（mention span 已存）；用户标 **正确 / 错误 / 存疑**
- 产出：每 KB 持久化 `review.json`（抽样历史 + 判定），面板显示 **抽样精确率**（如 "18/20 = 90%"）+ 低置信区间的单独精确率
- 闭环：标"错误"的关系进 `excluded` 清单——检索时过滤该边、统计口径单列；可一键从隔离区视角重放该 chunk（重抽）
- 体检报告（一键）：覆盖文件数/总数、隔离率、抽样精确率、最后索引时间、roots 外逃逸检查——一个可读的"该库能不能信"结论卡

### 4.3 明确不做

- 全量人工核对（成本不可行，抽样 + 分层已有统计代表性）
- 自动"准确性评分"包装成精确率承诺（抽样率不足时诚实标注样本量）

## 5. 实施切分（M3 重排）

| 周 | 内容 | 出口 |
|---|---|---|
| M3-W1 | KB 数据模型 + kbs.json 注册表 + 迁移 + provider v2 契约 + 工具 kb 参数 + 测试 | 旧库迁移后工具多库往返通过 |
| M3-W2 | Web RPC 通道 + KB 管理页 + 索引进度页（dsh client 面） | Web 建库→索引→进度可见 |
| M3-W3 | 图谱浏览页 + 抽样审查页 + 体检报告 | 抽样精确率闭环（标错→排除生效） |
