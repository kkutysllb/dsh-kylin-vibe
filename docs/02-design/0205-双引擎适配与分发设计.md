## 1. 宿主适配层

宿主差异全部收敛在 `src/adapter.ts`（工具 consumer 与 provider 通过它取宿主能力），核心库不感知宿主：

| 适配点 | dsh | QiLin | 适配函数 |
|---|---|---|---|
| 数据目录 | `$DSH_HOME/graphrag` → `~/.dsh/graphrag` | 宿主 home 约定（M3 实测落定，暂按 `~/.qilin/graphrag`） | `resolveDataDir(ctx)` |
| 调用者身份 | `exec.agent.session.{id, header.cwd}` 防御性解构 | 同构（已验证） | `callerFrom(exec)` |
| 审批挂钩 | agent scoped `tools/pre-execute` | 同构 | `mountApproval(scoped)` |
| 公告注入 | `ctx.systemPrompt` | 同构 | `announce(ctx)` |
| LLM 辅助调用 | `ctx.llm.stream()` + `RequestUserInput` | 同构 | `llmComplete(ctx, opts)` |
| 能力探测 | 服务存在性检查（`'llm' in ctx` 级别），不做版本硬依赖 | 同 | `capabilities(ctx)` |

探测失败的行为矩阵：无 `llm` → provider 以降级模式注册（词法/遍历可用，抽取/摘要/全局打分返回 `NO_PROVIDER`）；无 `tools` → 插件静默不挂载工具（例如 headless profile）；无 `storageDomain` → 用默认数据目录。

## 4. 构建设计（`scripts/build.mjs`）

- esbuild，入口 = 四个角色入口（index/provider/tool/config），bundle 到 `lib/*.js` + `sourcemap` + `dts`（或手写薄 d.ts）；
- external：全部 `@deepseek-ai/*`、`@qilin/*`、`zod`（peer 语义，不进产物）；
- **产物提交进仓**（`lib/` 不 gitignore）：安装期零构建，pnpm 无需构建许可（dsh-ragflow/automation 双验证）；
- 单产物双引擎：两个宿主读同一份 `lib/`（bundle 字段只是声明差异，无产物差异——本期无 client 面）；
- `smoke-plugin.mjs`：模拟宿主加载四入口，断言 `ctx.graphrag` 注册、工具注册面为 5、审批挂钩存在。

## 5. 测试策略

| 层 | 手段 | 覆盖 |
|---|---|---|
| 核心库单测 | `node:test` + 纯内存 GraphStore 桩（或 tempdir SQLite） | 分块边界、抽取解析修复、归并聚合、LPA 确定性（同图同标签）、PPR 收敛、遍历预算、checkpoint 状态机、隔离区、forget 级联 |
| provider 集成 | `ctx.llm` 桩（脚本化返回 fixture 抽取 JSON） | 管线端到端、失败码路由、成本计数、abort 续跑 |
| 工具契约 | `ctx.tools` 桩 + 参数 schema 校验 | 5 工具的参数/输出/错误文案、审批触发边界 |
| 宿主冒烟 | 两个宿主各跑 `smoke-plugin.mjs` + 手动一轮 index→query 往返 | 双引擎加载与注册面 |
| 冻结评测 | `tests/eval/`（见 0206） | 检索质量回归门 |

`register-dsh-stubs.mjs`：注入宿主服务的最小桩（`tools`/`llm`/`systemPrompt`/`storageDomain`），使全部测试不依赖宿主 checkout（学 automation 的测试隔离）。

## 6. 分发与安装

| 通道 | 命令 |
|---|---|
| npm | `dsh plugin --profile web add dsh-kylin-vibe` / `qilin plugin add dsh-kylin-vibe` |
| GitHub tag | `dsh plugin --profile web add github:kkutysllb/dsh-kylin-vibe#v0.1.0` |
| 本地开发 | `dsh plugin --profile web add link:/abs/path/dsh-kylin-vibe`（本仓） |
| 镜像 monorepo | `sync:mirror` 同步到 `dsh-plugins/dsh-kylin-vibe`（automation 流程复用） |

版本与更新：`package.json` version 驱动插件管理检测，用户手动更新；每版本 `release/vX.Y.Z.md` 变更说明。

发布验证清单（每次发版必过）：

1. `pnpm check` 全绿（typecheck + 单测/集成 + 双 bundle）；
2. `pnpm eval` 不低于上一版本基线（0206 回归门）；
3. dsh 宿主冒烟：安装 → 重启 → 工具注册面 5 → 最小索引（fixture 仓）→ local/global/traversal 三模式往返；
4. QiLin 宿主冒烟：同上；
5. 审批门实测：index 触发审批卡（双语）、拒绝后 `ABORTED` 可续跑。

## 7. 配置面（v1）

v1 无配置页，配置经 `cordis.patch.yml` 行 + 环境变量（学 dsh-ragflow 的分层，砍掉页面层）：

```yaml
- id: graphrag-provider-local
  config:
    roots: ['/abs/path/repo-a', '/abs/path/docs']   # 授权索引根（显式，ADR-9）
    exclude: ['.git', '.env*', '*secret*', '*.pem'] # 追加排除模式
    chunk: { targetTokens: 1000, maxTokens: 1400 }
    extract: { minConfidence: 0.6, repairRetries: 1, rateLimitRetries: 3 }
    community: { recomputeThreshold: 0.05, summaryMemberDrift: 0.3 }
    query: { ppr: { damping: 0.85, iterations: 20 }, localTopK: 25, globalBatches: 10 }
    model: { provider: null, model: null }          # null = 跟随宿主当前选择
```

环境变量覆盖：`GRAPHRAG_ROOTS`（冒号分隔）。配置读取全程防御性（patch 行 config 是普通对象，字段逐个 clamp——学 automation 的 Config 处理）。
