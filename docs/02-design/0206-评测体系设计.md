# 0206 · 评测体系设计（冻结评测集）

- 日期：2026-10-01
- 状态：定稿（实施基准）
- 上游依据：0101（DSH-RAG 冻结评测方法论）、ADR-5（向量后置的复审依据）

## 1. 为什么评测体系是 P0

两个来源的教训共同指向这一点：

- **DSH-RAG**：用冻结评测集否决了"AI 生成上下文摘要"特性（评测无提升即砍）——复杂度只有赢过基线才进主干；
- **graph-memory**：上下文压缩 −80% 的激进特性敢于上线，前提是检索质量可测。

GraphRAG 的实现复杂度远高于平铺 RAG（抽取质量、归并噪声、社区划分稳定性、PPR 参数……每个环节都可能引入回归）。**没有评测集，我们无法回答"图到底值不值"，也无法安全迭代。**

## 2. 评测集构成

### 2.1 语料（固定 fixture 仓）

`tests/eval/fixtures/` 内置两个固定语料（不随迭代改动）：

| 语料 | 规模 | 特点 |
|---|---|---|
| `fixture-knowledge/` | ~62 文件（Markdown 文档 + 少量代码，含 sitemap/changelog 干扰页） | 概念密度高，实体别名多（中英文混排），适合 local/global 评测 |
| `fixture-codebase/` | ~150 文件（TS 小型项目，含真实依赖结构） | 结构关系明确（imports/calls 可静态验证），适合 traversal 评测 |

抽取用的 LLM 调用在评测中走 **oracle 抽取器**（`tests/eval/oracle.ts`，**实现修订**：替代原设计的"录制/回放"机制——从冻结黄金 spec 派生完美抽取，比录制回放更确定且零缓存管理；模型升级不影响评测基线，真实 LLM 抽取质量另行在宿主冒烟评估）。

### 2.2 问题集（冻结）

`tests/eval/questions.json`：**v2 = 45 题**（v1 40 题 + 5 道多跳 local 题，changelog 版本化），三类型：

| 类型 | 数量 | 示例 | 评分方式 |
|---|---|---|---|
| local（关系性，含 5 道多跳） | 20 | "X 与 Y 通过什么机制关联？"（多跳：X 与 Z 无直接 spec 关系，答案须点名桥接实体） | hit@5 + MRR@5（排序敏感，门槛 v2 观测指标） |
| global（全局性） | 10 | "本项目的主要模块划分与职责？" | 关键点覆盖：标准答案要点的召回率 |
| traversal（影响/链路） | 15 | "修改 X 会影响哪些下游？" | 与静态分析黄金集的精确率/召回率 |

每题字段：`{id, type, question, golden: {entities[], relations[], points[], seedFile, goldenFiles[]}, notes}`（v2 补齐 notes 注记）。黄金答案**由 spec 派生冻结**（多跳题 golden 取 spec 两跳路径；本语料文本层稠密无严格"无共现"对，无共现按 spec 语义=无直接关系执行，changelog 如实记录）；改动需走 changelog 版本化记录，禁止"对着系统输出改答案"。

## 3. 基线与门槛

### 3.1 基线组（每次全量跑）

| 配置 | 意义 |
|---|---|
| `flat-bm25` | 纯 BM25/FTS Top-8 chunk（无图）——**平铺 RAG 基线**，图检索必须非劣于它，差异化能力（遍历/结构）必须赢它 |
| `graph-local`（PPR only，无社区摘要） | 图结构本身的贡献（global 门槛应失败——社区摘要价值由 graph-full 对比证明） |
| `graph-full` | 完整管线（含社区摘要/别名归并） |

### 3.2 门槛规则 v2（2026-10-03 定稿；v1 的相对阈值在基线贴天花板时超过指标上限 1.0，结构性不可达——M1 出口评审实证）

1. **门槛 1（local 非劣性）**：graph-full 的 entityHit@5 与 relationRecall 均不低于 `flat-bm25 − 0.02`（规则 4 的"持平"哲学）。MRR@5 为排序质量**观测指标**（含多跳题单列）——注意度量语义：实体层是去重排列（每个实体占一个位次，k 金标题结构上限 = Σ(1/i)/k，即 2 金标 0.75、3 金标 0.611），flat 的 chunk 位次允许多金标共享 rank 1（同块共现），两口径不直接可比，graph 侧应以「达结构上限的比例」读数；
2. **门槛 2（global 绝对差）**：coverage ≥ `flat-bm25 + 0.05`（社区摘要的价值证明；graph-local 无摘要时该门槛应失败——语义自校验）；
3. **门槛 3（traversal 双下限）**：精确率 ≥ 0.80 且召回率 ≥ 0.70（图遍历是确定性能力）；
4. **特性合入规则不变**：赢过合入前的 graph-full 或至少不回退（−2% 以内视为持平，需说明取舍）——ADR-5 向量复审的量化依据即来自此条。

**种子权重精化（2026-10-03 第二轮，questions v2.1）**：① 反查种子权重由原始出现次数改为**文档秩加权和**（rank r 的命中块贡献 1/r）——原 count 被「枢纽实体高频出现于任意命中块」与 sitemap 类枚举页污染（实测「对账」以 count=14 压过词法直击权重 12 排到第 1）；② 呈现序由严格分层改为**种子分 ⊕ PPR 分凸组合**（各按最大值归一各占一半）——分层曾把 PPR 强的桥接实体挡在种子层后，凸组合让「词法直击」与「图邻近」各执一半（0203 §2.1 同步修订）；③ 修正 v2 题集两处实体名笔误（风控→风控服务、营销服务→促销服务；题面/golden 实体组/golden 关系端点一并对照 spec 修正，changelog v2.1——2 字名「风控」无法构成 trigram，属无效题面）。终版：**MRR@5 0.6771（多跳 0.5778）**，对结构上限 0.6944（= (12×0.75 + 8×0.611)/20）达成率 **97.4%**——11/15 v1 题与 2/5 多跳题已达各自上限，relationRecall 顺带 0.95→1.00；余量属边际排序（如 L19 桥接实体第 7 vs 第 3），继续压缩即过拟合，止步。flat 同轮 0.9750（其口径允许多金标共享位次，仅作参照线）。

v2 首测（2026-10-03，questions v2 / oracle 抽取 / 45 题）：graph-full 三门槛全过（hit 1.0 / relRecall 1.0 非劣 ✅；coverage 0.9417 vs 0.875 +0.067 ✅；traversal P 0.945 / R 1.000 ✅）；graph-local 门槛 2 正确失败（摘要贡献 0.875→0.9417）。

### 3.3 回归门（CI）

- `pnpm eval` 输出记分卡（JSON + Markdown 表）提交到 `tests/eval/scorecards/<ts>-<config>.md`（git sha 记于文件内）；
- 发版检查单（0205 §6）要求：本次发版分支的最新记分卡不低于上一发版基线；
- 指标除质量外还记录：索引 LLM 调用数/token（oracle 模式如实记 0）、local 查询 P95 延迟、**库体积**（oracle 落盘 db 字节数）——**成本与性能同屏**，防"质量换成本"的隐性回退。

## 4. 评测执行器设计

```
tests/eval/run.ts
  --suite local|global|traversal|all（白名单校验）
  --config flat-bm25|graph-local|graph-full
流程：oracle 建图（落盘临时库，同路径可测库体积）→ 逐题执行 → 按类型评分
     （graph 配置同场重算 flat 基线）→ 汇总记分卡 + 门槛 v2 判定
```

评分实现要点：

- local hit@5 / MRR@5：证据包 `entities[].name` + `chunks` 文本与 `golden.entities` 的别名组匹配（大小写不敏感；MRR 取 golden 组在配置原生排序——图配实体层序 / flat chunk 序——中的倒数排名均值，@5 截断）；
- global 覆盖：`chunks` + `communities` 文本中 golden 要点关键词的命中比例（关键词表随黄金答案冻结）；
- traversal：返回子图的边集与静态黄金图求 PR；
- 全部评分函数纯函数化，自带单测（评分器本身不能是黑箱）。

## 5. 与开发的耦合纪律

1. **问题集先于实现**：M1 第一周产出问题集 v1 并冻结，随后才写检索代码（先有尺子再有刀）；
2. **禁止对着系统输出修黄金答案**：发现题目歧义 → 记录 → 显式版本化修订（`questions.v2.json` + changelog 理由）；
3. LLM 缓存刷新（模型升级）= 显式事件，重跑全量并重定基线，在 release notes 中记录指标变化；
4. 评测集不得用于调参过拟合：参数敏感性实验只在 20% 的开发题集上做，冻结集只做门禁（学冻结评测的通用纪律）。
