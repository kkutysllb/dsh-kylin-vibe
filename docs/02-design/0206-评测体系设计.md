# 0206 · 评测体系设计（冻结评测集）

- 日期：2026-10-01
- 状态：定稿（实施基准）
- 上游依据：0101（DSH-RAG 冻结评测方法论）、ADR-5（向量后置的复审依据）

## 1. 为什么评测体系是 P0

两个来源的教训共同指向这一点：

- **DSH-RAG**：用冻结评测集否决了"AI 生成上下文摘要"特性（评测无提升即砍）——复杂度只有赢过基线才进主干；
- **graph-memory**：上下文压缩 −80% 的激进特性敢于上线，前提是检索质量可测。

GraphRAG 的实现复杂度远高于平铺 RAG（抽取质量、归并噪声、社区划分稳定性、PPR 参数……每个环节都可能引入回归）。**没有评测集，我们无法回答"图到底值不值"，也无法安全迭代。**

## 2. 评测集构成

### 2.1 语料（固定 fixture 仓）

`tests/eval/fixtures/` 内置两个固定语料（不随迭代改动）：

| 语料 | 规模 | 特点 |
|---|---|---|
| `fixture-knowledge/` | ~60 文件（Markdown 文档 + 少量代码） | 概念密度高，实体别名多（中英文混排），适合 local/global 评测 |
| `fixture-codebase/` | ~150 文件（TS 小型项目，含真实依赖结构） | 结构关系明确（imports/calls 可静态验证），适合 traversal 评测 |

抽取用的 LLM 调用在评测中走 **fixture 录制模式**：首次运行录制真实 LLM 响应缓存为 fixture（`tests/eval/llm-cache/`），此后回放——评测可重复、零成本、不因模型升级而漂移（模型升级时显式 `--refresh-cache` 重录并重定基线）。

### 2.2 问题集（冻结）

`tests/eval/questions.json`：**40 题**，三类型：

| 类型 | 数量 | 示例 | 评分方式 |
|---|---|---|---|
| local（关系性） | 15 | "X 与 Y 通过什么机制关联？" | hit@5：标准答案实体/关系是否出现在证据包 |
| global（全局性） | 10 | "本项目的主要模块划分与职责？" | 关键点覆盖：标准答案要点（实体/主题清单）的召回率 |
| traversal（影响/链路） | 15 | "修改 X 会影响哪些下游？" | 与静态分析黄金集（fixture-codebase 用 ts 简单 import 图生成）的精确率/召回率 |

每题字段：`{id, type, question, golden: {entities[], relations[], points[], paths[]}, notes}`。黄金答案**人工标注后冻结**（改动需走 `eval-changelog` 记录，禁止"对着系统输出改答案"）。

## 3. 基线与门槛

### 3.1 基线组（每次全量跑）

| 配置 | 意义 |
|---|---|
| `flat-bm25` | 纯 BM25/FTS Top-8 chunk（无图）——**平铺 RAG 基线**，图检索必须赢它 |
| `graph-local`（PPR only，无社区摘要） | 图结构本身的贡献 |
| `graph-full` | 完整管线（含社区摘要/别名归并） |

### 3.2 门槛规则（进入主干的条件）

1. `graph-full` 在 local 题上 hit@5 **≥ `flat-bm25` + 15%**（相对提升）——否则图的复杂度不成立，回炉；
2. `graph-full` 在 global 题上要点覆盖 **≥ `flat-bm25` + 20%**——社区摘要的价值证明；
3. traversal 题精确率 **≥ 80%** 且召回率 **≥ 70%**（对照静态黄金集）——图遍历是确定性能力，不应低；
4. 任何特性合入（向量、Leiden 分层、新分块策略……）：必须在冻结集上**赢过合入前的 `graph-full`** 或至少不回退（−2% 以内视为持平，需说明取舍）——ADR-5 向量复审的量化依据即来自此条。

### 3.3 回归门（CI）

- `pnpm eval` 输出记分卡（JSON + Markdown 表）提交到 `tests/eval/scorecards/<date>-<sha>.md`；
- 发版检查单（0205 §6）要求：本次发版分支的最新记分卡不低于上一发版基线；
- 指标除质量外还记录：索引 LLM 调用数/token、local 查询 P95 延迟、库体积——**成本与性能同屏**，防"质量换成本"的隐性回退。

## 4. 评测执行器设计

```
tests/eval/run.ts
  --suite local|global|traversal|all
  --config flat-bm25|graph-local|graph-full
  [--refresh-llm-cache]
流程：准备 fixture 索引（录制/回放 LLM）→ 逐题执行 → 按类型评分 →
     汇总记分卡 → 与上一基线 diff → 超门槛则更新 baseline.json
```

评分实现要点：

- local hit@5：证据包 `entities[].name` + `relations` 三元组与 `golden.entities/relations` 的规范化名匹配（复用核心库 `norm_name`）；
- global 覆盖：`chunks` + `communities` 文本中 golden 要点关键词的命中比例（关键词表随黄金答案冻结）；
- traversal：返回子图的边集与静态黄金图求 PR；
- 全部评分函数纯函数化，自带单测（评分器本身不能是黑箱）。

## 5. 与开发的耦合纪律

1. **问题集先于实现**：M1 第一周产出问题集 v1 并冻结，随后才写检索代码（先有尺子再有刀）；
2. **禁止对着系统输出修黄金答案**：发现题目歧义 → 记录 → 显式版本化修订（`questions.v2.json` + changelog 理由）；
3. LLM 缓存刷新（模型升级）= 显式事件，重跑全量并重定基线，在 release notes 中记录指标变化；
4. 评测集不得用于调参过拟合：参数敏感性实验只在 20% 的开发题集上做，冻结集只做门禁（学冻结评测的通用纪律）。
