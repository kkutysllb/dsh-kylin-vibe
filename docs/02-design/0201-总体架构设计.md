# 0201 · 总体架构设计

- 日期：2026-10-01
- 状态：定稿（实施基准）
- 上游依据：0101（生态调研）、0102（技术路线）、0103（双引擎兼容）、0104（ADR）

## 1. 设计原则

1. **三角色分离**：seam 定义服务契约，provider 实现引擎，consumer 面向模型/人员消费；角色间只依赖 seam。
2. **核心零宿主依赖**：GraphRAG 引擎是纯 TS 库，不 import 任何宿主包，可脱离宿主单测（学 dsh-kylin-automation 测试桩模式）。
3. **图谱导航、原文举证**：一切图数据带 `source_chunks` 引用，社区摘要标记为二手信息（学 graph-memory）。
4. **成本显式**：一切触发 LLM 调用的路径都有审批门或显式工具调用，插件自身零凭据。
5. **本地优先**：无外部服务依赖；无 provider 配置时词法/图遍历路径仍然可用。

## 2. 角色与插件入口

一个 npm 包 `dsh-kylin-vibe`，`cordis.patch.yml` 拆行注册（seam/provider/rpc/tool 四行；原规划的 `config.ts` 配置页入口被 0207 §3 的 rpc + client inject 形态取代）：

| 角色 | 入口 | inject | 职责 |
|---|---|---|---|
| **Service Definition（seam）** | `src/index.ts` → `dsh-kylin-vibe` | `[]`（实测修订：宿主 0.2.0 的服务经 `reflect.provide/get` 挂取，不经 `storageDomain`；数据目录由 provider 配置决定） | 拥有 `ctx.graphrag`：GraphRagService 契约、provider 注册表、顺序无关选择 |
| **Service Provider** | `src/provider.ts` → `.../provider` | `graphrag`（seam）、`llm`（鸭子型非严格读取） | 本地引擎：ingest 管线、抽取（宿主 llm，模型显式配置 > 会话路由跟随）、图存储（node:sqlite）、LPA、社区摘要、三种检索模式 + global LLM 分批打分 |
| **Consumer（RPC 通道）** | `src/rpc.ts` → `.../rpc` | `graphrag`、`webServer`、`connection` | `/dsh-kylin-vibe` 面板通道（0207 §3）：snapshot/KB 管理/索引/进度/浏览/审查/体检端点 |

## 4. GraphRagService 契约（seam 面；v2 多知识库形态见 0207 §2.2）

```ts
export interface GraphRagService {
  /** provider 注册（provider.ts 调用）；同 id 重复注册抛错。返回注销函数。 */
  register(provider: GraphRagProvider): () => void
  /** 顺序无关选择：恰好一个可用 → 选中；多个 → 需配置 pin；零个 → 明确错误。 */
  resolve(pin?: string): GraphRagProvider
}

export interface GraphRagProvider {
  readonly id: string                                  // 'local-sqlite'
  // KB 管理面（0207 §2.2）
  listKbs(): KnowledgeBase[]
  createKb(input): KnowledgeBase
  updateKb(id, patch): KnowledgeBase
  deleteKb(id): ForgetReport
  // 检索面（KbRef 定位；query/traverse/forget 的 cwd 参与默认解析链）
  status(target?: KbRef): Promise<IndexStatus>
  index(target: KbRef, opts: IndexOptions, signal: AbortSignal, sessionId?: string): Promise<IndexReport>
  indexBackground(target: KbRef, opts, sessionId?): { started: boolean }   // 面板/工具主路径
  progress(kbId): IndexProgress | null
  cancelIndex(kbId): boolean
  query(target: KbRef | undefined, q: QueryInput, cwd?: string): Promise<EvidencePack>
  traverse(target: KbRef | undefined, t: TraverseInput, cwd?: string): Promise<Subgraph>
  forget(target: KbRef | undefined, inner: ForgetTarget, cwd?: string): Promise<ForgetReport>
  estimate(target, opts, cwd?): { files: number; estCalls: number }        // 审批卡 dry-run
  // 浏览与审查面（0207 §3.3/§3.4，面板专用）
  browseEntities / communityList / evidenceText / sampleForReview / reviewRelation / healthReport
  // 知识管理面（v0.1.2+，面板专用）
  listKnowledge / addTextKnowledge / forgetKnowledge / reindexKnowledge / setKnowledgeEnabled
  importFiles / importDirectory / changesPreview / graphAll / expandNode / correctFromSelection
}
```

要点：

- **KB 一等实体（0207）**：每 KB 独立存储 `<dataDir>/kbs/<id>/graphrag.db`；默认解析链 id → name → ①cwd 命中唯一库 → ②唯一库 → ③`KB_AMBIGUOUS` 候选名单。
- `index` 必须接受 `AbortSignal`（审批拒绝/会话取消即中断，checkpoint 保证可续）；宿主工具/面板路径走 `indexBackground`（立即返回，进度轮询）——0.2.0 宿主实测工具调用 5 分钟预算装不下前台索引。
- 查询零 LLM 的模式（local/traverse）在 provider 内部短路；global 模式 >8 社区时 LLM 分批打分（10 个/批，词法兜底），`QueryMeta` 透出调用数与 token 数。

## 5. 数据流（三条主链路）

### 5.1 索引（写路径，审批门后）

```
graphrag_index(roots?) → 授权校验(realpath/排除规则) → 扫描(hash 对比)
  → dirty 文件集 → 分块 → 抽取(ctx.llm, 每chunk一次) →[失败→隔离区]
  → 实体归并/边聚合 → LPA(若图结构变化超阈值) → 受影响社区摘要重算(ctx.llm)
  → checkpoint 推进 → IndexReport(成本/新增/跳过/隔离计数)
```

### 5.2 推理查询（读路径，agent 主用）

```
graphrag_query(mode=local)  → FTS5 种子 → PPR 排序 → 证据包(实体+边+chunk原文+社区摘要)
graphrag_query(mode=global) → 社区摘要分批 LLM 打分 → reduce → 证据包(社区摘要+代表实体+chunk引用)
graphrag_graph              → 实体定位 → BFS 遍历(方向/跳数/边类型过滤) → 结构化子图(零LLM)
```

### 5.3 治理（低频）

```
graphrag_status → 覆盖面/规模/隔离区/陈旧度/ provider 健康
graphrag_forget(文件|实体|整图) → 审批门 → 级联删除 + 社区指纹失效 → ForgetReport
```

## 6. 关键横切关注点

| 关注点 | 设计 |
|---|---|
| 人工审批 | `tools/pre-execute` 挂钩：`graphrag_index`、`graphrag_forget` 触发 `ask`（`reason` 审计文案 + `displayReason` 本地化，仅 allow 时升级拦截） |
| 能力公告 | `systemPrompt` 注入一段 ≤400 字公告（实测 393 字）：五工具名册 + 三条非显然约束 |
| 并发 | 同库索引互斥：面板/工具路径走 `indexBackground`（已有索引在跑 → `started:false` + 提示，不阻塞 agent）；查询与索引并发（WAL 模式） |
| 取消与恢复 | 全管线 `AbortSignal` 贯穿；文件级 checkpoint（source.state + extraction_batch）；启动时发现 running 残留批次自动标 aborted 并重入 |
| 可观测 | 工具返回有界（chunk 4000 字截断）；LLM 调用计数与 token 估算进 `IndexReport`/`QueryMeta`；面板进度带 phase/LLM/token/隔离计数 |
| 失败语义 | 稳定错误码（`NOT_AUTHORIZED`/`NOT_INDEXED`/`NO_SEED`/`AMBIGUOUS_SEED`/`KB_AMBIGUOUS`/`QUARANTINED`/`NO_PROVIDER`/`MISSING_CREDENTIAL`/`ABORTED`/`LLM_TIMEOUT`/`CONTEXT_WINDOW`/`INVALID`/`SCHEMA_FUTURE`；`INDEX_IN_PROGRESS` 保留映射），工具层转成模型可读的短文案，审计层保留码 |

## 6a. 实现修订记录（对本文档初版的落地偏差，2026-10-03 审计回写）

1. seam 不再 inject `storageDomain`：宿主 0.2.0 实测服务属性访问需 `reflect.get(name, false)` 非严格读取，`storageDomain` 面不可用；数据目录链见 0205 §1 实测修订。
2. 第四入口由规划的 `config.ts` 配置页演化为 `rpc.ts` + `src/client/`（模块表装载，0207 §3 Web 面板形态）；`cordis.patch.yml` 四行 = seam/provider/rpc/tool。
3. 运行时依赖由「仅 zod」扩为 `zod + fflate + unpdf`（v0.1.2 二进制文档/图片抽取，用户裁定提前实施 ADR-11 范围，见 0203 §1.4 修订）。
4. 仓库布局：`core/graph.ts`（归并）并入 `graphstore.applyExtraction`；`quarantine.ts` 并入 store；`search-local/global/traversal` 合并为 `search.ts`；新增 `kb.ts`（KB 注册表）、`extract-doc.ts`（二进制文档）、`src/client/`（面板五件套 + GraphView）、`src/dts/`（手写薄 d.ts）。

## 7. 与三个参照项目的架构映射

| 参照 | 我们吸收的架构元素 |
|---|---|
| dsh-ragflow | 三角色四入口打包；seam 上 `resolve()` 顺序无关选择；未来外部引擎 provider 一行替换 |
| graph-memory | 核心库零宿主依赖 + 适配层吸收宿主差异；隔离区；"导航不举证"原则 |
| dsh-kylin-automation | package.json 双引擎字段、类型垫片、审批双字段、能力公告、构建/测试/分发流水线 |

## 8. 演进路径（架构层面预留）

- **外部引擎 provider**（RAGFlow/Neo4j）：实现 `GraphRagProvider` 接口 + patch 一行即可，工具面与评测集不动；
- **embedding provider 缝**：`lexical.ts` 后并一个 `vector.ts`（同接口），按 ADR-5 复审条件启用；
- **记忆插件**：如需对话记忆场景，另立插件复用本核心库（chunk 来源模型不同，见 0102 §5）。
