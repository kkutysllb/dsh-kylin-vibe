# 0201 · 总体架构设计

- 日期：2026-10-01
- 状态：定稿（实施基准）
- 上游依据：0101（生态调研）、0102（技术路线）、0103（双引擎兼容）、0104（ADR）

## 1. 设计原则

1. **三角色分离**（学 dsh-ragflow）：seam 定义服务契约，provider 实现引擎，consumer 面向模型/人员消费；角色间只依赖 seam。
2. **核心零宿主依赖**：GraphRAG 引擎是纯 TS 库，不 import 任何宿主包，可脱离宿主单测（学 dsh-kylin-automation 测试桩模式）。
3. **图谱导航、原文举证**：一切图数据带 `source_chunks` 引用，社区摘要标记为二手信息（学 graph-memory）。
4. **成本显式**：一切触发 LLM 调用的路径都有审批门或显式工具调用，插件自身零凭据。
5. **本地优先**：无外部服务依赖；无 provider 配置时词法/图遍历路径仍然可用。

## 2. 角色与插件入口

一个 npm 包 `dsh-kylin-vibe`，`cordis.patch.yml` 拆四行注册（M1-M2 期三行，M3 加配置页行）：

| 角色 | 入口 | inject | 职责 |
|---|---|---|---|
| **Service Definition（seam）** | `src/index.ts` → `dsh-kylin-vibe` | `storageDomain` | 拥有 `ctx.graphrag`：GraphRagService 契约、provider 注册表、顺序无关选择、数据目录定位 |
| **Service Provider** | `src/provider.ts` → `.../provider` | `graphrag`（seam）、`llm` | 本地引擎：ingest 管线、抽取（ctx.llm）、图存储（node:sqlite）、LPA、社区摘要、三种检索模式 |
| **Consumer（工具）** | `src/tool.ts` → `.../tool` | `graphrag`、`tools`、`systemPrompt` | 五个 agent 工具 + 能力公告段 + `tools/pre-execute` 审批门 |
| **Consumer（配置页，M3）** | `src/config.ts` → `.../config` | `graphrag`、`webServer`、凭据无关 | 只读图可视化 + 索引进度页（可 disable） |

## 4. GraphRagService 契约（seam 面）

```ts
export interface GraphRagService {
  /** provider 注册（provider.ts 调用）；同 route 重复注册抛 DUPLICATE_PROVIDER */
  register(provider: GraphRagProvider): () => void
  /** 顺序无关选择：恰好一个可用 → 选中；多个 → 需配置 pin；零个 → 明确错误 */
  resolve(): GraphRagProvider
}

export interface GraphRagProvider {
  readonly id: string                                  // 'local-sqlite'
  status(cwd: string): Promise<IndexStatus>
  index(cwd: string, opts: IndexOptions, signal: AbortSignal): Promise<IndexReport>
  query(cwd: string, q: QueryInput): Promise<EvidencePack>
  traverse(cwd: string, t: TraverseInput): Promise<Subgraph>
  forget(cwd: string, target: ForgetTarget): Promise<ForgetReport>
}
```

要点：

- **按 `cwd`（工作区）隔离索引**：一个工作区一张图，互不串扰；数据目录 = `resolveDataDir(ctx)` 下按工作区 hash 分目录（适配层吸收 dsh/QiLin 差异，见 0103 §4）。
- `index` 必须接受 `AbortSignal`（审批拒绝/会话取消即中断，checkpoint 保证可续）。
- 查询零 LLM 的模式（local/traverse）在 provider 内部短路；global 模式的 LLM 打分调用由 provider 发起，走 `ctx.llm`。

## 5. 数据流（三条主链路）

### 5.1 索引（写路径，审批门后）

```
graphrag_index(roots?) → 授权校验(realpath/排除规则) → 扫描(hash 对比)
  → dirty 文件集 → 分块 → 抽取(ctx.llm, 每chunk一次) →[失败→隔离区]
  → 实体归并/边聚合 → LPA(若图结构变化超阈值) → 受影响社区摘要重算(ctx.llm)
  → checkpoint 推进 → IndexReport(成本/新增/跳过/隔离计数)
```

### 5.2 推理查询（读路径，agent 主用）

```
graphrag_query(mode=local)  → FTS5 种子 → PPR 排序 → 证据包(实体+边+chunk原文+社区摘要)
graphrag_query(mode=global) → 社区摘要分批 LLM 打分 → reduce → 证据包(社区摘要+代表实体+chunk引用)
graphrag_graph              → 实体定位 → BFS 遍历(方向/跳数/边类型过滤) → 结构化子图(零LLM)
```

### 5.3 治理（低频）

```
graphrag_status → 覆盖面/规模/隔离区/陈旧度/ provider 健康
graphrag_forget(文件|实体|整图) → 审批门 → 级联删除 + 社区指纹失效 → ForgetReport
```

## 6. 关键横切关注点

| 关注点 | 设计 |
|---|---|
| 人工审批 | `tools/pre-execute` 挂钩：`graphrag_index`、`graphrag_forget` 触发 `ask`（`reason` 审计文案 + `displayReason` 本地化，旧宿主回落） |
| 能力公告 | `systemPrompt` 注入一段 ≤400 字公告：什么问题用 `graphrag_query`（全局/关系性）vs 自带 grep（精确文本）；三条非显然约束 |
| 并发 | 同工作区索引互斥（进程内锁 + SQLite 事务）；查询与索引可并发（WAL 模式） |
| 取消与恢复 | 全管线 `AbortSignal` 贯穿；文件级 checkpoint 表；启动时发现 interrupted 状态自动标记可续 |
| 可观测 | 每次工具返回携带 bounded 摘要行（学 automation 的 `definitionSummary` 模式）；LLM 调用计数与 token 数进 `IndexReport`/`QueryMeta` |
| 失败语义 | 稳定错误码（`NO_PROVIDER`/`NOT_INDEXED`/`QUARANTINED`/`ABORTED`...），工具层转成模型可读的短文案，审计层保留码 |

## 7. 与三个参照项目的架构映射

| 参照 | 我们吸收的架构元素 |
|---|---|
| dsh-ragflow | 三角色四入口打包；seam 上 `resolve()` 顺序无关选择；未来外部引擎 provider 一行替换 |
| graph-memory | 核心库零宿主依赖 + 适配层吸收宿主差异；隔离区；"导航不举证"原则 |
| dsh-kylin-automation | package.json 双引擎字段、类型垫片、审批双字段、能力公告、构建/测试/分发流水线 |

## 8. 演进路径（架构层面预留）

- **外部引擎 provider**（RAGFlow/Neo4j）：实现 `GraphRagProvider` 接口 + patch 一行即可，工具面与评测集不动；
- **embedding provider 缝**：`lexical.ts` 后并一个 `vector.ts`（同接口），按 ADR-5 复审条件启用；
- **记忆插件**：如需对话记忆场景，另立插件复用本核心库（chunk 来源模型不同，见 0102 §5）。
